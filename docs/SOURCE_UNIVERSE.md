# Source Universe & Provider Strategy

**Review date:** 2026-09-30
**Purpose:** Identify source classes worth evaluating before adding providers. This is an audit, not an integration plan or claim that listed sources are available to PMB.

## Principles and current status

- Card identity is normalized application data; pricing observations and artwork are provider evidence/representations, not Binder identity.
- TCGdex is currently the configured Pokémon catalog and artwork provider. That is an implementation choice, not an architectural limitation or an endorsement of TCGdex as the owner of canonical identity, pricing, or artwork.
- Pricing and artwork providers are independent, domain-specific adapters. A provider may be added without making it a field or authority in the core Binder model. No general plugin marketplace or universal provider registry is implemented.
- Absence of a listing, price, or image means **no observation**, not a price of zero.
- A “core candidate” means worthy of a bounded feasibility follow-up for a particular kind of evidence, not approved for production.
- Publicly viewable pages, public APIs, a free tier, or a software/data-code license do not by themselves grant permission to scrape, store, transform, cache, or redistribute images or data. Review access terms, rate limits, attribution, and licensing before implementation.
- The **₱0 baseline** remains a product constraint. Do not assume a source, proxy, storage tier, API quota, or licensing path is free just because browsing is public.

## Pricing source candidates

An observation must identify what it measures. A completed sale, active seller ask, retailer price, buylist offer, and aggregated guide value are not interchangeable. Raw/graded status, condition, printing/variant, language, market, currency, and timestamps must be recorded when supplied; otherwise mark them unknown rather than infer them.

The current default market-value calculation consumes only observations
explicitly classified as `price-guide`. A caller may deliberately select one
other transaction class, but incompatible classes are not combined by default.
V1 does not require a backend, login, paid APIs, or marketplace scraping; this
inventory does not approve or integrate additional providers.

### Independence and consolidation

- An adapter/provider name and a marketplace name are separate facts. TCGdex currently reports price fields labelled Cardmarket and TCGplayer; until upstream lineage and observation semantics are verified, this does not establish that the data are independent transaction samples.
- PriceCharting explicitly includes sold eBay data in its methodology. Its values must not be counted as an independent source beside the same eBay sales.
- A retailer ask, marketplace ask, buylist offer, auction close, and price guide answer different questions. Store and compare them by evidence class; never blend simply because they are numeric and in the same currency.
- The existing median is unchanged. The observation contract carries source type, geography, transaction/listing type, qualitative source confidence, and lineage. Default market-value consolidation now accepts only explicitly tagged `price-guide` observations; callers must select one other class explicitly. Cross-class aggregation is not supported, and missing transaction classes are excluded by default.
- Existing currency conversion/market reference behavior does not establish local Philippine completed-sale coverage. Foreign-market values need original currency and an appropriately dated conversion; they are not PHP transactions.

## Artwork and image source candidates

Three image purposes remain separate:

1. **Catalog artwork** is a representative card image associated with an exact printing.
2. **Recognition/reference artwork** is a controlled set of visual references used to identify photographed cards; it may need language, printing, promo, and alternate-art variants.
3. **User physical-card photographs** depict a particular copy and may include sleeves, glare, damage, or counterfeit evidence. Scanner inputs/references remain separate from catalog artwork and are not automatically suitable for shared cache or display.

## Contract and registry boundary

- `CanonicalCardIdentity` holds normalized printing fields and generic namespaced `providerIds`; it does not require a TCGdex ID. Legacy `tcgdexId`/identity image fields are normalized away at the artwork-provider boundary. `Card.id` remains the current catalog record key for compatibility with the existing catalog/Binder path; a future replacement catalog would need its own migration/identity decision rather than assuming IDs are globally interchangeable.
- A `Card` may carry a source-tagged `catalogArtwork` reference. Existing `imageUrlLow`/`imageUrlHigh` remain compatibility slots for existing records. Artwork providers receive canonical identity plus optional tagged catalog artwork; they do not need a TCGdex ID.
- Artwork candidates preserve provider (`source`), provider card ID (`sourceCardId`), display URL, optional original/cache URLs, language/variant, quality, confidence, verification, usage eligibility, provenance, and provider-reported retrieval time. `resolvedAt` remains the resolver's timestamp, not an upstream retrieval timestamp.
- The artwork resolver accepts **catalog artwork only**. Recognition references and user photographs have separate scanner/reference types and flows; they are not provider artwork candidates.
- Pricing observations preserve adapter (`source`) separately from marketplace (`market`), plus optional source class, market country/region, language, variant, condition/grading, transaction type, listing status, currency, observation/fetch times, qualitative confidence and lineage. Confidence is descriptive metadata, not a calibrated score or weighting rule.
- Provider registration remains code-controlled and domain-specific: artwork uses `ArtworkProvider`/`ArtworkProviderRegistration`, pricing uses `PricingProvider`, catalog uses `CatalogProvider`/`ICatalogProvider`, and recognition uses the scanner's `ScannerProvider`. There is no shared dynamic extension marketplace.
- Artwork confidence, when supplied, is validated to the 0–1 range and retained as provider metadata; it is not treated as a calibrated probability or used to override explicit provider priority.

## Next implementation decision

Do not add providers from this inventory in bulk. First select one evidence need (for example, authorized eBay active listing asks, a Japanese completed-auction reference, or a rights-cleared alternate artwork source), verify exact printing coverage, access/terms, lineage, rate limits, and whether it fits ₱0, then write a bounded adapter proposal. Until that decision, TCGdex remains the only production Pokémon catalog/artwork provider and the only configured live pricing adapter.
